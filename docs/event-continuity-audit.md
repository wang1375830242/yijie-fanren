# 事件连续性评审

日期：2026-10-24  
状态：已修复

## 发现

### 1. 孤儿身世仍会出现父母问话

`渔村孤儿` 的出身文本明确写「父母死于风灾」，但早期 `age_5`、`root_test`、`age_15`、童年场景和 `AMBIENT` 仍使用「母亲」「父亲」「父母」等称呼。

修复：

- `Sim` 根据出身设置 `flags.no_parents`
- `familyText()` 统一替换为「收养你的老人」「抚养你的人」
- `events-expanded.fill()` 对生成事件做同样处理
- `trigger()` 对事件正文、选项 label、静态 outcome 统一处理
- `q_letters` 明确排除无父母出身

### 2. 人界事件串入灵界/仙界

早期 `q_market`、`q_valley`、`q_herb` 等事件的 `when` 只判断境界，没有判断世界；灵界本地出生也可能看到凡人坊市、宗门落霞谷。

修复：

- `pickEvent()` 对 `c_`、`q_`、`f_`、`h_`、`g_h_`、`age_`、`root_` 等前缀加人界门禁
- 灵界/仙界只能进入各自世界事件池

### 3. 事件临时选项污染

坊市弹窗曾把「拿不出灵石」追加到全局事件 choices。

修复：

- `trigger()` 克隆 choices
- 临时选项只存在于本回合

## 第二轮：事件池审计

又检查了事件池的条件和关系状态：

- `n_` 事件默认属于人界，已加入非人界门禁；灵界/仙界不会触发凡人收徒、结婴等事件。
- `n_disciple` 原来用 `s.disciples.length` 判断，已改为只数在世弟子；旧弟子去世后仍可再收徒。
- `q_valley` 原来炼气与筑基共用，且缺少世界门禁；现在限定人界炼气期。
- 道侣生成事件原来只排除「异地」，会误触发死亡/疏远道侣；现在要求 `alive !== false` 且 `status === "present"`。
- 父母相关文本统一走 `familyText()`，事件正文、选项 label、静态 outcome 都会被处理。

仍需注意：

- 事件仍以独立随机场景为主，前后因果不会像主線那样强；如果要更强关联，应单独设计「事件链」，不要在现有随机池里硬塞因果。
- 「父母」只是人物在场的一种，后续可扩展为 `npcStates`（父母/道侣/弟子/仇敌）供事件条件查询。
- 事件池仍有大量生成文本，建议后续增加「人物在场」「地点」「年龄」三类上下文键，而不仅是世界门禁。
- 读屏与 320px 已做浏览器可访问性树检查，但仍建议人工用 Narrator/NVDA 走一遍完整人生。
