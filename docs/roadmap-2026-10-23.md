# 《一介凡人》下一阶段路线图

日期：2026-10-23  
状态：路线评审已完成，暂不写代码

## 一、当前基线

已完成：

- 转世道果与下一世继承
- 宗门职位与贡献
- 弟子 / 对手养成线
- 后期节奏压缩与事件保底
- 结局分类与一生三幕回顾
- 碑林 39 位原著人物
- 事件总数 3065

当前最需要补的不是“更多事件”，而是**可靠性、中期内容密度和跨局留存**。

## 二、四身份评审结论

本轮用同一模型分四个身份评审：内容与世界观、系统与长期目标、技术与体验、反方与留存。

### 共识

1. **没有中途续存是最高风险体验问题**  
   一次关页、切后台或刷新，可能丢掉整局十几分钟，并且当前道果在开局时就会被标记使用。

2. **中期内容仍然偏空**  
   筑基到元婴阶段有大量通用事件，但缺少专属主线和地域/宗门身份感。

3. **转世道果目前只是一次性礼包**  
   没有谱系、没有前世档案，长期重玩动机仍然弱。

4. **不要再加程序化事件数量**  
   继续堆 ID 不会解决“换皮感”，应扩场景、选择和语义差异。

### 分歧

- 内容身份主张先做中期主线，因为这是玩家停留最久的一段。
- 系统身份主张先做转世谱系，把跨局留存补成闭环。
- 技术与反方身份都主张先做存档续存，认为丢局是当前第一流失点。

## 三、优先级路线

### P0 · 存档与可靠性（最优先）

> 状态：已实现，设计细节见 [p0-save-design.md](p0-save-design.md)。

**目标**：关页不丢这一世；换设备能带走；道果不会因为误关页面而作废。

改动：

- 新增 `yijie.save.v1`：保存 seed、RNG 状态、裁剪后的 `sim.state`、选项与版本号
- 每步或每隔 N 步节流自动保存；进入 `play.html` 时提供「继续上一世 / 重新降生」
- 修复道果消费时机：确认开局成功后才 `markLegacyUsed`，失败时保留
- 给 `state.log`、`state.textUse` 设上限或窗口裁剪，避免长局存档膨胀
- 新增存档导入：about 页支持 JSON 导入，按 seed 去重，坏文件给中文提示
- 种子回放：复制带 seed 的只读链接
- 新增 GitHub Actions：`node --check` + `canon-regression.js`

规模：S–M  
依赖：无  
验收：

- 中途刷新 8/8 次能回到相同年龄、境界、待决选项
- 关闭页面后道果不被误消费
- 导出 → 换浏览器导入，人生记录条数与内容一致
- 长局存档小于 200KB
- 220 局回归与 `worst-repeat <= 2` 保持

### P1 · 中期主线与身份内容（第二优先）

**目标**：让筑基、结丹、元婴不只靠通用池。

改动：

- 一条中期主线「残图」：得图 → 结伴/夺图 → 入殿，三步用 flag 串联
- 每个区域 8 条地域专属事件（越国、天南、大晋、乱星海）
- 每个可加入宗门 2–3 条身份事件（门规、称谓、内斗、任务）
- 主线事件使用现有 `when` / flag，不新增 pending 类型
- 只扩内容，不增加事件 ID 数量

规模：M  
依赖：建议在 P0 后接入存档，避免长主线被刷新打断  
验收：

- 带对应 flag 的局在 200 年内 100% 出现下一步
- 四个区域各至少 8 条事件能在对应出生地命中
- 中期主线触发率 ≥ 70%
- 220 局 0 issue，单世重复 ≤ 2

### P2 · 转世谱系与碑林元目标（第三优先）

**目标**：让“再投一世”有可追溯的长期记录。

改动：

- `yijie.lineage.v1`：保存最近 20 世，记录前世姓名、境界、死因、道果
- 终局页显示「第 N 世」和上一世道果
- 碑林增加「已读碑 / 已点灯 / 已达成」进度
- 6 个跨局成就：首次飞升、首次长老、连续三世、道侣同界、善因/业债等
- 导出导入同时携带 legacy 与 lineage

规模：M  
依赖：P0、P1  
验收：

- 三世后 lineage 长度为 3，旧档缺失字段不报错
- 清除本机记录时明确提示谱系会一起丢失
- 成就只解锁一次，旧记录可正常渲染

### P3 · 场景池与语义去重（可与 P1 并行）

**目标**：继续降低“换皮感”，但不增加事件 ID。

改动：

- 童年场景从约 20 个扩到 60 个，其他主题场景从 8 个扩到 20 个
- 去重键从精确文本升级为 `sceneKey + 选择结果类型`
- 同一场景整世最多出现 3 次
- 旧 `textUse` 数据兼容

规模：M  
依赖：无  
验收：

- 单世事件正文与选择结果重复 ≤ 2
- 生涯前 10 个事件跨局重复率从接近 100% 降到 60% 以下
- 事件总数不增加也能感到场景变化

### P4 · 经济与体验加固（后置）

- 各境界灵石价格带与稳定消耗口
- 洞府/灵田/弟子月例等长期支出
- 移动端触控、焦点管理、`localStorage` 写满提示
- 日志虚拟滚动与长局性能

规模：S–M  
依赖：P0、P2  
验收：各境界都能买到 1–3 件有用物品；长局 1000 步不卡死；键盘可完成一次完整抉择。

## 四、新增扩展项（暂不实施）

### P5 · 姓名性别匹配

**目标**：避免男角色叫明显女名、女角色叫明显男名。

计划：

- 将现有 `GIVEN` 名字池拆为 `MALE_GIVEN`、`FEMALE_GIVEN`、`NEUTRAL_GIVEN`
- 主角、道侣、弟子、对手、同劫等生成姓名时按性别选择
- 少量中性名可跨界使用，用于保留随机性
- 已有存档中的旧名字不改；只影响新人生成
- 姓名池可与出身地 lightly 匹配，但不强制复杂地域姓氏系统

验收方向：

- 男角色不再高频生成明显女名
- 女角色不再高频生成明显男名
- 道侣、弟子、对手姓名也遵守同一规则
- 旧记录读取不报错

### P6 · 再一世前世回响

**目标**：转世不只是数值继承，还能在剧情里遇到前世相关的人和事。

计划：

- 基于现有道果与未来的转世谱系数据，记录上一世的姓名、境界、重要关系、未了因果
- 新增低频回响事件：
  - 上一世故人转世/后人寻访
  - 前世仇家认出气息
  - 前世道侣遗留书信、旧物或墓碑
  - 前世宗门遗迹中读到自己的旧名
  - 上一世未完成的因果找上门
- 命中条件需要克制，避免每局都出现“我前世是谁”的重复桥段
- 与转世道果共用数据，但不把前世身份直接公开成强提示；保留模糊感

验收方向：

- 连续二世时有一定概率出现前世回响事件
- 旧存档无前世数据时正常降级
- 前世相关事件不破坏单世文本重复规则
- 事件强度低于主线，不替代当前人生

## 五、明确不做

- 继续增加 1000 条程序化事件
- 把 95 位图鉴人物全部变成每局 NPC
- 账号、云存档、公共排行榜、留言审核等后端功能
- 重写全部 3065 条事件文案
- 为追求“市场感”引入构建链、外部字体或第三方统计

## 六、最终建议

如果只能选一个，选 **P0 存档与可靠性**。

理由：

1. 它解决的是玩家会真实流失的问题，而不是“内容不够多”
2. 它顺手修复道果被提前消费的现有缺陷
3. P2 的谱系、P1 的长主线都需要存档作为地基
4. 不修改数值平衡，风险最低，验收最明确

P0 完成后的顺序：

```text
P0 存档与可靠性
  ↓
P1 中期主线与身份内容
  ↓
P2 转世谱系与碑林元目标
  ↓
P3 场景池与语义去重（可与 P1 并行）
  ↓
P4 经济与体验加固
```
