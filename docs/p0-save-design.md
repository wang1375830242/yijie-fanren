# P0：存档、续存与种子回查

日期：2026-10-23  
状态：已实现并通过本地回归

## 一、评审结论

采用 **快照续存 + 轻量选择轨迹** 的混合方案：

- 快照负责刷新续玩，减少对事件结构与 pending 序列化的依赖
- `choiceTrace` 负责问题回查，真正复现玩家走过的分支
- 不做完整可视化回放，避免把 P0 扩大成回放引擎

单独一个 seed 只能复现出生、灵根和初始世界，不能保证复现玩家实际选择；要定位具体问题需要 seed + trace。

## 二、运行中快照

存储键：

```text
yijie.run.v1
```

内容：

```json
{
  "v": 1,
  "seed": 123456,
  "world": "human",
  "mode": "birth",
  "rng": { "state": 123, "calls": 45 },
  "socialRng": { "state": 456, "calls": 12 },
  "state": {},
  "pace": "mid",
  "savedAt": "2026-10-23T..."
}
```

规则：

- 只在没有 `pending` 的稳定点保存
- 每步结束、抉择完成、冲关、购物、切换重心后保存
- 页面隐藏时尝试保存
- `state.log` 保留最后 600 条，`history` 保留最后 400 条，`choiceTrace` 保留最后 500 条
- 刷新后提示「发现一段未完成的人生，继续吗？」
- 结束、重新降生、清空数据时清除运行快照

## 三、道果消费修正

- 不再在 `startLife()` 创建 Sim 后立刻消耗道果
- 只有运行快照成功写入后，才标记道果已使用
- 因此开局后立即关页不会误吞道果
- 恢复快照时不会二次应用道果

## 四、导入导出

关于页支持：

- 导出：人生记录、灯、道果、运行中快照
- 导入：合并人生记录、灯（取较大值）与事件；满 60 条时优先保留新导入；可选恢复运行中快照
- 新人生 ID 带时间后戳，避免同 seed 多局共用碑位；旧 ID 继续兼容
- 坏文件、版本不兼容、重复记录都有中文提示
- 清空数据会同时清理运行快照与道果

## 五、种子回查包

游戏内菜单「复制回查包」输出：

```json
{
  "v": 1,
  "seed": 123456,
  "world": "human",
  "mode": "birth",
  "age": 240,
  "tier": 3,
  "realm": "结丹期",
  "trace": [
    { "age": 15, "tier": 1, "kind": "event", "eventId": "age_15", "choice": 2 }
  ]
}
```

说明：

- `trace` 记录事件/选项、濒死选项、冲关动作
- 只有 seed 时，开发侧可以查初始生成和数值问题
- seed + trace 才能定位“同一局为什么出现某个分支”
- 完整自动回放暂未开放为玩家界面，避免 P0 范围膨胀

## 六、验收

- 中途刷新恢复年龄、境界、资源与稳定点状态
- RNG 恢复后保持同一随机序列
- 快照不包含 pending，不会丢函数
- 导出后导入不重复人生记录
- 旧人生记录无新字段时正常渲染
- 本地回归 199+ checks、220 局无异常
